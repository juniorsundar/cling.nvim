# cling.nvim — Glossary (Domain Model)

> Generated by the grill-with-docs skill. Terms are defined as *what the
> concept is*, not merely what it does. Locations cite `lua/` paths relative to
> the plugin root.

---

## CommandNode

**Definition:** A plain Lua table that is the unit of the completion tree. It
is a record of at most three fields: `flags` (an ordered array of strings),
`subcommands` (a map from subcommand name to another `CommandNode`), and
`completion_type` (an optional hint, absent or `nil` unless set). It is *not* a
class instance; there is no metatable, constructor, or method dispatch — the
"class" exists only as an annotation.

- **Current location:** Declared as an annotation at `lua/cling/parser.lua:3-6`.
  Constructed as bare table literals throughout the codebase.
- **Proposed location:** Owned by a new `lua/cling/command_node.lua`; the
  `@class` annotation and a single `new()` constructor move there so the shape
  is defined in exactly one file.
- **Relationships:** Is the node type of a **completion tree**; is produced by
  **crawlers** and `parse*`; is consumed by `serialize` and `find`; is persisted
  as the **cache file** payload.

---

## Completion tree

**Definition:** The recursive value produced by parsing a CLI's surface — a
rooted `CommandNode` whose `subcommands` map recursively contains child nodes.
It is the in-memory model of "what subcommands, flags, and file/dir hints a CLI
offers at each level."

- **Current location:** No single home. Rooted per-wrapper at
  `lua/cling.lua:192`; also rooted at `lua/cling/jobs/generator.lua:23` and
  `lua/cling/crawlers/completion_script_crawler.lua:81-83`.
- **Proposed location:** The **command_node** module owns build (parse),
  persistence (serialize), and query (`find`) over the tree; the shape lives in
  one place.
- **Relationships:** Composed of **CommandNode**s; produced by **crawlers** /
  `parse*`; serialized into a **cache file**; queried to yield **completion
  candidates**.

---

## Wrapper

**Definition:** A user-supplied configuration record (a table) describing how
to expose one CLI binary as a Neovim user command. Its fields include `binary`,
`command`, one of the completion methods (`help_cmd`, `completion_cmd`,
`completion_file`), plus execution options (`cwd`, `close_on_exit`, `keymaps`,
`no_history`, `on_close`).

- **Current location:** Documented in `doc/cling.nvim.txt` (WRAPPER FIELDS
  section) and consumed in `lua/cling.lua:191-292`.
- **Proposed location:** Unchanged (stays a config concern in `cling.lua`); the
  refactoring does not move wrapper shape, only the completion-tree logic it
  triggers.
- **Relationships:** Triggers **generator** subprocess; feeds
  `ensure_completion`; produces one **completion tree** per wrapper.

---

## completion_type

**Definition:** An optional per-node field whose value is the string `"dir"` or
`"file"`. It is a declarative hint that, at this node, completions should come
from filesystem entries (directories or files) rather than only from
`flags`/`subcommands`.

- **Current location:** Declared `lua/cling/parser.lua:6`; set only by
  `parse_bash` at `lua/cling/parser.lua:139-155`; read by the completion closure
  at `lua/cling.lua:235-239`; serialized by `lua/cling/utils.lua:33-35`.
  **Asymmetry:** `parse_help` never sets it and `completion_script_crawler`
  never sets it.
- **Proposed location:** Owned by `command_node`; `find()` and `serialize` both
  read it from there.
- **Relationships:** A field of **CommandNode**; interpreted into **completion
  candidates** by `find`; part of the **cache file** schema.

---

## flags

**Definition:** A field of a `CommandNode`: an ordered array of option strings
valid at that node's command level (e.g., `--verbose`, `-v`, `--flag1`).

- **Current location:** Declared `lua/cling/parser.lua:4`; populated in
  `parse_help`, `parse_bash`, and `completion_script_crawler.lua`; serialized at
  `utils.lua:36-40`; walked at `cling.lua:227-230`.
- **Proposed location:** A field owned by `command_node`, constructed via a
  single constructor and consumed by `find`/`serialize`.
- **Relationships:** Field of **CommandNode**; source of flag **completion
  candidates**.

---

## subcommands

**Definition:** A field of a `CommandNode`: a map whose keys are subcommand-name
strings and whose values are child `CommandNode`s, forming the recursive
structure of the tree.

- **Current location:** Declared `lua/cling/parser.lua:5`; populated in
  `parse_help`, `parse_bash`, and `completion_script_crawler.lua`; serialized at
  `utils.lua:43-50`; walked at `cling.lua:209-213,221-225`.
- **Proposed location:** A field owned by `command_node`; recursion over it is
  centralized in `find`.
- **Relationships:** Field of **CommandNode**; the recursion edge of the
  **completion tree**; source of subcommand **completion candidates**.

---

## Completion candidate

**Definition:** A single string offered to Neovim's command-completion engine
for the current cursor position. It can be a subcommand name, a flag, the
special `--reparse-completions` token (at root only), or a filesystem path
derived from `completion_type`.

- **Current location:** Assembled in the `complete_func` closure at
  `lua/cling.lua:219-245`.
- **Proposed location:** Assembled by `command_node.find` (and, if separated,
  any filesystem candidate expansion injected into or layered over it).
- **Relationships:** Output of `find`; derived from **flags**, **subcommands**,
  **completion_type**, and **arglead**; consumed by
  `nvim_create_user_command`'s `complete` callback.

---

## arglead

**Definition:** The first argument Neovim passes to a `:command`-completion
callback: the word fragment currently being completed (the part of the command
line the cursor is on). It is *not* the whole command line.

- **Current location:** Received at `lua/cling.lua:201`
  (`complete_func = function(arglead, cmdline, _)`) and used for tree-descent
  stop (`cling.lua:208-210`), filesystem completion (`cling.lua:236`), and
  prefix filtering (`cling.lua:242`).
- **Proposed location:** Passed unchanged into
  `command_node.find(node, args, arglead)`.
- **Relationships:** Input to `find`; used to filter **completion candidates**.

---

## Crawler

**Definition:** A component that harvests a CLI's external completion surface
and converts it into a `CommandNode`/completion tree. Two concrete kinds exist:
the help crawler (recursive `--help` text scraping) and the completion-script
crawler (BFS over a Bash completion function via
`scripts/get_completion.bash`).

- **Current location:** `lua/cling/crawlers/help_crawler.lua` (recursive
  `crawl`, depth limit 4 at `:28-33`; calls `parser.parse_help` at `:46`);
  `lua/cling/crawlers/completion_script_crawler.lua` (BFS `build_tree` at
  `:77-150`; constructs node literals directly at `:81-83` and `:126-131`, and
  does *not* call `parser`).
- **Proposed location:** Unchanged as separate crawler modules, but they should
  call `command_node.new()` instead of writing `{ flags = {}, subcommands = {} }`
  literals.
- **Relationships:** Produce **completion trees**; invoked by the **generator**
  subprocess; both are out-of-process crawlers.

---

## Generator

**Definition:** The detached subprocess entrypoint script
(`nvim -l lua/cling/jobs/generator.lua`) that receives
`(plugin_root, outfile, binary, method, value)`, dispatches to the appropriate
**crawler**, and persists the resulting tree. It is the only place that crosses
the main-process/subprocess boundary for completion generation.

- **Current location:** `lua/cling/jobs/generator.lua`; argument parsing
  `:7-14`; runtime-path prepend `:16`; dispatch `:31-73`; persistence `:79-80`.
- **Proposed location:** Stays the subprocess entrypoint; its
  `utils.serialize`/`utils.write_file` calls become `command_node.serialize`
  plus a relocated I/O helper.
- **Relationships:** Invokes **crawlers**; calls `serialize`; writes the
  **cache file**; is spawned by `ensure_completion` (`lua/cling.lua:66-90`).

---

## Cache file

**Definition:** A persisted Lua source file at
`stdpath("data")/cling/completions/<binary>.lua` whose entire content is a
`return <serialized CommandNode>` expression. It is the on-disk artifact that
lets later startups skip re-crawling.

- **Current location:** Path built at `lua/cling.lua:36-38`; read/loaded at
  `cling.lua:40-45` and `:78-80`; written by `generator.lua:79-80` via
  `utils.serialize` + `utils.write_file`.
- **Proposed location:** Unchanged path and (ideally) byte-compatible format;
  its schema is now defined by `command_node.serialize` rather than
  `utils.serialize`.
- **Relationships:** Serialized form of a **completion tree**; produced by
  **generator**; consumed by `ensure_completion`; schema includes **flags**,
  **subcommands**, **completion_type**.

---

## Seam

**Definition:** A deliberate boundary in the code structure where one
responsibility meets another, and where behavior can be swapped, tested, or
isolated without changing the rest of the system. The proposed `command_node`
module is a seam that concentrates the build/persist/query lifecycle; the
`nvim -l` generator subprocess is a second, process-level seam.

- **Current location:** Implicit: the `vim.system({ "nvim", "-l", ... })` call
  at `lua/cling.lua:66-76` is the process seam; the module `require` boundaries
  (`cling.parser`, `cling.utils`) are the module seams.
- **Proposed location:** Explicit: `lua/cling/command_node.lua` becomes the
  single seam for tree shape/lifecycle.
- **Relationships:** Separates `cling.lua` (orchestration) from **CommandNode**
  mechanics; separates the main process from the **generator**.

---

## The "deletion test"

**Definition:** A design heuristic for module cohesion: a module passes if it
can be deleted as a unit and its responsibilities vanish coherently (you can
name the single thing it owns); it fails if deletion would leave scattered,
unrelated responsibilities or require re-homing unrelated code. Applied to
`utils.lua`: it fails because it bundles generic file I/O (`write_file`/
`read_file`, used by core/history/generator for three unrelated purposes) with a
completion-tree-specific serializer that hard-codes node field names.

- **Current location:** Heuristic applied to `lua/cling/utils.lua`
  (`write_file` `:3`, `read_file` `:13`, `serialize` `:28-59`); its consumers
  are `lua/cling/core.lua:142-143`, `lua/cling/history.lua:72-73`, and
  `lua/cling/jobs/generator.lua:68,79-80`.
- **Proposed location:** `utils.lua` is deleted; generic I/O moves to a small
  single-purpose helper or is inlined, and `serialize` moves into
  `command_node`.
- **Relationships:** Justifies the deletion in the ADR; distinguishes
  "node-specific" code from "generic" code.

## `--reparse-completions`

**Definition:** A synthetic, root-only candidate injected into completions
(`lua/cling.lua:232-234`) and intercepted in the command callback
(`lua/cling.lua:253-255`) to force regeneration. It is a hard-coded special
case with no representation in the tree itself.

- **Current location:** `lua/cling.lua:232-234` (injection) and
  `:253-255` (interception).
- **Proposed location:** The caller in `setup()` appends it after
  `command_node.find()` returns, when at root. `command_node` stays clean of
  plugin-specific knowledge. The closure is ~5 lines, not 3, but the boundary
  is honest. (Resolved in ADR-001, Q2.3.)
- **Relationships:** Not a field of **CommandNode**; a plugin-level concern
  layered on top of **completion candidates**.

---

## Navigation (module)

**Definition:** The module (`lua/cling/navigation.lua`) that owns
terminal-output navigation: turning a line of terminal output into a
navigable file location, and exporting terminal buffer content to a file. It
is the seam where the `<CR>` jump and `ge` export behaviours live, behind a
small interface that tests can reach with plain buffers and temp files — no
terminal jobs required.

- **Current location:** Does not exist. The behaviour is inline in
  `core.executor`'s keymap callbacks (`lua/cling/core.lua:213-258` for `<CR>`,
  `:289-294` for `ge`/`export_output` at `:117-151`).
- **Proposed location:** `lua/cling/navigation.lua`. Two functions:
  `jump_to(line, cfile, cwd, target_win)` and `export(buf, cmd, cwd, filepath)`.
  The executor's keymap callbacks shrink to thin calls that extract cursor
  state and delegate.
- **Relationships:** Called by **executor** (via keymap callbacks); operates on
  the **terminal output buffer**; uses **DEFAULT_EFM** to parse locations;
  `export` writes via `cling.fs`.

---

## jump_to

**Definition:** The function that converts a line of terminal output into a
file open action. Given the current line text, the `<cfile>` under the cursor,
the working directory, and a target window, it: trims the line to start from
`cfile`, parses the trimmed line with **DEFAULT_EFM** to extract `lnum`/`col`,
resolves the file path relative to `cwd`, and opens the file in the target
window via `win_execute` with the cursor positioned at the parsed line/column.

- **Current location:** Inline in the `<CR>` keymap callback at
  `lua/cling/core.lua:213-258` (~45 lines).
- **Proposed location:** `navigation.jump_to(line, cfile, cwd, target_win)` in
  `lua/cling/navigation.lua`. The keymap callback in executor shrinks to ~4
  lines that extract `nvim_get_current_line()` and `expand("<cfile>")` and
  delegate.
- **Relationships:** Uses **DEFAULT_EFM** for parsing; called by **executor**'s
  `<CR>` keymap callback; opens files in the **target window**.

---

## export (navigation)

**Definition:** The function that writes terminal buffer content to a file,
appending a metadata footer. Given a buffer handle, the command that produced
the output, the working directory, and a filepath, it: reads all buffer lines,
strips trailing empty lines, appends a four-line metadata footer (Command, CWD,
ISO 8601 Timestamp, `vim: ft=log` modeline), and writes the result.

- **Current location:** `export_output` free function at
  `lua/cling/core.lua:117-151`. Called by the `ge` keymap callback at
  `:289-294`.
- **Proposed location:** `navigation.export(buf, cmd, cwd, filepath)` in
  `lua/cling/navigation.lua`. The interactive prompt (`vim.fn.input`) stays
  in the executor's `ge` keymap callback; `export` receives the resolved
  filepath and owns the rest.
- **Relationships:** Called by **executor**'s `ge` keymap callback; reads from
  the **terminal output buffer**; writes via `cling.fs.write_file`.

---

## DEFAULT_EFM

**Definition:** A module-local constant in `navigation.lua` that concatenates
three errorformat patterns — `%f:%l:%c:%m`, `%f:%l:%c`, `%f:%l` — used to parse
terminal output lines into file locations (filename, line number, column). It
replaces the inline `temp_efm` literal in the current `<CR>` handler, giving
the format a name and a single home.

- **Current location:** Inline literal at `lua/cling/core.lua:226-230`,
  constructed fresh on every `<CR>` press, unnamed.
- **Proposed location:** Module-local `local DEFAULT_EFM` in
  `lua/cling/navigation.lua`, defined once. Callers never see it — it is not
  a parameter and not exported.
- **Relationships:** Used by **jump_to** to parse lines via
  `vim.fn.getqflist({ lines = {...}, efm = DEFAULT_EFM })`.

---

## Terminal output buffer

**Definition:** The Neovim buffer (typically a terminal buffer) created by
**executor** to display the output of a shell command. It is the input for both
navigation operations: `jump_to` reads the current line from it (via the
cursor), and `export` reads all lines from it. It is identified by its buffer
handle (`M.cling_buffer` in `core.lua`).

- **Current location:** Created at `lua/cling/core.lua:191`
  (`M.cling_buffer = vim.api.nvim_get_current_buf()`), named `[Cling]` at
  `:194`.
- **Proposed location:** Unchanged — still created and owned by **executor**.
  Navigation receives it as a parameter (`buf` in `export`) or reads from it
  indirectly (`line`/`cfile` in `jump_to`, extracted by the caller).
- **Relationships:** Created by **executor**; read by **jump_to** (via caller)
  and **export** (directly); has `q`, `<CR>`, and `ge` keymaps wired by
  executor.

---

## Location (parsed)

**Definition:** The result of parsing a terminal output line with
**DEFAULT_EFM**: a quickfix list item containing `filename` (or `bufnr`),
`lnum` (line number), and `col` (column, possibly 0). Only `lnum` and `col` are
consumed by **jump_to** — the filename is *not* used for path resolution (the
`cfile` from the cursor is used instead, which is a known limitation).

- **Current location:** `qf_items[1].lnum` and `qf_items[1].col` at
  `lua/cling/core.lua:240-241`, accessed with no guard on empty results.
- **Proposed location:** Same access pattern inside `navigation.jump_to`.
  The `lnum`/`col` are used to construct the `edit +<lnum> <path> | normal!
  <col>|` command for `win_execute`.
- **Relationships:** Produced by `vim.fn.getqflist` with **DEFAULT_EFM**;
  consumed by **jump_to**; the filename field is ignored (known limitation).

## Marker

**Definition:** The `@` character used as an opt-in prefix that converts a
following special token from shell-literal text into an expansion site. The
marker is *not* shell syntax and never reaches the shell: it is consumed by
Cling when (and only when) immediately followed by a recognized token. Any
other `@` passes through verbatim, and a doubled marker (`@@`) yields a
single literal `@`. It exists so that Cling commands stay shell-literal by
default — Vim-standard semantics are requested explicitly rather than
assumed.

- **Current location:** Does not exist. Introduced by ADR-003.
- **Proposed location:** Recognized only inside the new expansion module's
  scanner; no other component may interpret `@` specially.
- **Relationships:** Precedes a **token** to form an expansion site;
  consumed during **expansion**; escaped by doubling (`@@`). Defined in
  ADR-003.

---

## Expansion

**Definition:** Cling-side rewriting of marked tokens into concrete strings
(the resolved file path, cursor word, etc.) *before* the command line is
handed to the shell. Expansion happens at execution time, not at input or
history-recording time: stored history entries remain raw, and every
re-execution path re-expands against the then-current buffer and working
directory.

- **Current location:** Does not exist. Introduced by ADR-003.
- **Proposed location:** A dedicated pure transformation module
  `(raw command line, execution CWD) → expanded command line`, hooked into
  the raw-line entry points after prompts resolve.
- **Relationships:** Consumes **marker** + **token** sequences; applies
  **modifier chains**; resolves relative forms against the execution CWD;
  runs downstream of history recording and upstream of executor
  environment-file prefixing. Defined in ADR-003.

---

## Token

**Definition:** One of the recognized special units that a **marker** can
prefix: `%` (current file), `#` (alternate file), `#<number>` (buffer N's
file), `<cword>` / `<cWORD>` (word / whitespace-delimited WORD under the
cursor), and `<cfile>` (file path under the cursor). Autocommand-context
(`<afile>`, `<abuf>`, `<amatch>`) and script-context (`<sfile>`, `<slnum>`)
tokens are deliberately outside the set — they are meaningless in Cling's
execution context and would silently expand to empty strings.

- **Current location:** Do not exist as expansions today; `%`, `#`, `<`, `>`
  pass through to the shell with their ordinary shell meanings.
- **Proposed location:** Enumerated once, inside the expansion module's
  scanner — the single source of truth for what counts as expandable.
- **Relationships:** Target of a **marker**; optionally carries a
  **modifier chain**; cursor-based tokens read editor state through an
  injected context provider. Defined in ADR-003.

---

## Modifier chain

**Definition:** An ordered sequence of colon-suffixed path modifiers applied
left-to-right to a **token** within one marked site (e.g. `%:p:h:t`). Three
families are supported: path modifiers (`:p`, `:~`, `":."`), anatomy
modifiers (`:h`, `:t`, `:r`, `:e`), and shell-safety modifiers (`:S`, `:q`).
Substitution modifiers (`:s///`, `:gs///`) are excluded by design.
Modifiers resolve against the *execution* CWD: each token resolves to an
absolute path first, and relative forms are then recomputed against the CWD
chosen at the second prompt.

- **Current location:** Do not exist. Today no modifier syntax is honored in
  Cling command lines.
- **Proposed location:** Parsed and applied inside the expansion module,
  immediately after token recognition; unsupported modifiers terminate
  recognition so the site falls back to passthrough.
- **Relationships:** Suffix of a **token** inside an expansion site; applied
  during **expansion**; `:S`/`:q` produce shell-quoted output for filenames
  containing spaces. Defined in ADR-003.
